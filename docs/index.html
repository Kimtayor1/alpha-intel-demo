这套演示做了什么、没做什么

  • 做了什么：合成事件进流程 → 本地规则给出决策草案 → 去重判定 → 生产原版验证器按 strict 路径校验 → 得出 PUSH/NO_PUSH → 写进模拟发件箱。
  • 没做什么：不抓取任何平台、不调任何 API、不发通知、不监控联网、不读环境变量、不加载外部 CDN 或字体。
  • 审核不是 AI：页面里的"审核"由 docs/lib/pipeline.js 的规则分支产生，是确定性 mock，用来演示流程与拦截点。
  • 证据链接：演示用 .invalid 保留域名，浏览器永远不会解析；x.com 下的句柄与 ID 带 fictitious 字样，只为满足校验器的"原始 X 来源"字符串要求，页面按纯文本展示，不做可点链接。
